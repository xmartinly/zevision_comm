# Zevision 发布说明

## 版本

- 当前版本:**0.10.0** (预发布;没有 0.9.2)
- 公司:INFICON;作者:martin.liang@inficon.com (写在 `AssemblyInfo.cs` 的 `AssemblyDescription` 和 `AssemblyMetadata("Author")` 中,文件属性的"备注"可见)
- 版本号只在 `Properties/AssemblyInfo.cs` 中修改:`AssemblyVersion`、`AssemblyFileVersion` 和 `AssemblyInformationalVersion`。
- 标题栏和 `logs\error.txt` 的会话标题都显示 `AssemblyInformationalVersion`。

## 构建

```
"C:\Program Files (x86)\Microsoft Visual Studio\2019\Community\MSBuild\Current\Bin\MSBuild.exe" Zevision.sln -restore -t:Rebuild -p:Configuration=Release -nologo -v:minimal
```

- Release 配置开启了 `TreatWarningsAsErrors`,构建必须 0 警告。
- 发布前运行全部单元测试,必须全部通过:

```
%USERPROFILE%\.nuget\packages\xunit.runner.console\2.9.3\tools\net472\xunit.console.exe Zevision.Tests\bin\Release\Zevision.Tests.dll
```

## 发布文件 (`bin\Release\`)

发布包中程序目录只放 `Zevision.exe`、`Zevision.exe.config`、`Texts.json` 和使用说明,下表中的 dll 都放在 `lib\` 子文件夹 (由 `Zevision.exe.config` 的 `<probing privatePath="lib" />` 指定;开发时 dll 在 exe 旁边,同样能找到)。

| 文件 | 说明 |
|---|---|
| `Zevision.exe` | 主程序 (内嵌图标和版本信息) |
| `Zevision.exe.config` | 运行时配置 (dll 所在的 `lib` 子文件夹、程序集绑定重定向),必须随 exe 一起发布 |
| `Zevision.Communication.dll` | 通讯库 (传输、帧、响应解析),程序必需 |
| `Zevision.Commands.dll` | 指令库 (指令集、命令生成),程序必需 |
| `Zevision.Core.dll` | 业务层 (设备访问、仪器配置读写、恢复计划),程序必需 |
| `Zevision.Storage.dll` | 存储层 (配置文件、`settings.json`、错误日志、通讯数据文件),程序必需 |
| `Texts.json` | 业务层和存储层的中英文提示与错误文本 (翻译文件),程序必需;缺少或格式错误时程序提示后退出。可以修改翻译 (UTF-8,每条都要有 `zh` 和 `en`,`{0}` 等占位符要保留) |
| `MaterialDesignThemes.Wpf.dll` | 界面主题 |
| `MaterialDesignColors.dll` | 界面主题颜色 |
| `Microsoft.Xaml.Behaviors.dll` | MaterialDesignThemes 的依赖 |

另附 .NET Framework 运行库安装文件 (见"打包"):

| 文件 | 说明 |
|---|---|
| `dotnet\ndp48-x86-x64-allos-enu.exe` | .NET Framework 4.8 离线安装包 (Microsoft 官方,`https://go.microsoft.com/fwlink/?linkid=2088631`,Microsoft 数字签名)。程序以 4.7.2 为目标,4.8 是就地升级、完全兼容,且是仍支持 Windows 7 SP1 的最新版本 (4.8.1 不支持 Win7)。只在缺少运行库的电脑上需要。 |

**不要**发布:

- `*.pdb` (调试符号,留档备查即可)
- `settings.json` (每台电脑自己的通讯配置,首次运行会自动生成)
- `logs\`、`recipe\` (运行时生成的日志和用户的配置文件)

## 打包

用脚本打包 (0.10.0 起),输出到 `dist\` (不随源码分发):

```
powershell -ExecutionPolicy Bypass -File tools\package.ps1
```

脚本依次:Release 重新构建并运行全部单元测试 (`-SkipBuild` 跳过) → 组装发布文件夹 → 核对 .NET 安装包的数字签名 → 压缩 → 输出 SHA256 → 把 zip 解压到临时目录启动一次,确认标题栏的版本后关闭 (程序已在运行时跳过并提示手动检查:单实例)。版本已存在时拒绝覆盖。

- `dist\Zevision-<版本>\`:
  - 程序目录:`Zevision.exe`、`Zevision.exe.config`、`Texts.json`、`使用说明.md` (即 `docs/USER_GUIDE.md`)、`User Guide.md` (即 `docs/USER_GUIDE.en.md`)
  - `lib\`:上表的 7 个 dll
  - `dotnet\ndp48-x86-x64-allos-enu.exe`:默认取 `dist` 中最近一个发布包里的,或用 `-DotNetInstaller` 指定。脚本核对数字签名 (签名者 Microsoft Corporation,状态 Valid)。
- `dist\Zevision-<版本>.zip`:上述文件夹的压缩包,即发布包。把脚本输出的 SHA256 填入下面的版本表。
- `dist\symbols\Zevision-<版本>\`:exe 和 4 个 dll 的 pdb (0.9.x 只有 `dist\symbols\Zevision-<版本>.pdb`),留档用于分析用户反馈的异常堆栈,不发布。

不要在 `dist\Zevision-<版本>\` 中直接启动 (会生成 `settings.json`、`logs\`)。

## 0.10.0 更新内容 (相对 0.9.6)

- 分层重构 (功能、界面文字和错误日志内容不变):
  - 硬件通讯层与协议解析层:`Zevision.Communication.dll`、`Zevision.Commands.dll` (结构未变)。
  - 业务逻辑层:新的 `Zevision.Core.dll` (设备访问、仪器配置读写、恢复计划、修改配置时与设备和文件的同步)。
  - 数据存储层:新的 `Zevision.Storage.dll` (配置文件、`settings.json`、错误日志、通讯数据文件),实现业务层定义的接口。
  - 界面层 (`Zevision.exe`) 只依赖业务层的接口,存储层只在程序启动时组装。
  - 业务层和存储层的提示与错误文本集中在翻译文件 `Texts.json` (中英文),放在程序旁边。
- 发布包结构:程序目录只有 `Zevision.exe`、`Zevision.exe.config`、`Texts.json` 和使用说明,全部 dll 在 `lib\` 子文件夹。升级时删除旧版本程序目录中的 dll (或解压到新文件夹),`settings.json`、`recipe\`、`logs\` 保留。由 `tools\package.ps1` 生成。
- 修正 RS232 读取配置失败 (2026-10-18 实测):设备的 RS232 校验和、长度字节都开着 (G1304 = G1305 = 1),但 `?` 的响应以不带长度和校验和的整帧发来,程序把开头的 `?+` 当作长度,报告"缺少停止符",其余约 80 KB 显示为"帧外数据"并写入 error.txt。解码器现在能识别这种响应 (`Zevision.Communication` 1.0.1,公开接口不变)。
- 数据显示区:帮助指令 (`?`、`?M` 等) 只在指令输入框中发送时显示;保存、恢复、修改配置时读取设备用的帮助指令及其响应不再显示,也不保存到通讯数据文件、不计入收发帧数。取消读取后设备仍在发送的剩余数据也不显示。
- 修正内存泄漏:修改配置窗口关闭后不能被回收,每打开一次多占约 40 MB (托管内存;进程私有内存约 50 MB),多次打开后程序越来越占内存。现在关闭后全部释放。
- 减少弹窗 (用户要求,2026-10-18):成功不再弹窗,出错仍然弹窗。
  - 主窗口:保存配置成功、恢复配置成功、"与文件一致,无需修改" 只记录在数据显示区;恢复完成但有项无法写入时仍弹窗。
  - 修改配置窗口:保存、新建、删除、添加/删除列表项成功的结果显示在窗口底部;列表的 **+** 和工艺的膜层 **添加** 不再确认 (可以删除)。其他确认框 (写入、恢复、新建、删除、删除列表项、放弃未保存的修改、切换语言) 不变。
- 修改配置窗口:"设置"页只为看得见的行生成控件 (虚拟化)。膜系页"全部展开"由约 1 秒、55 MB 降到约 0.1 秒、22 MB,勾选、筛选、滚动更快;外观和操作不变。
- 帧格式与设备不一致时说明原因:程序与设备的长度字节设置不同 (如程序关闭了长度和校验和,设备的 G1407/G1408 仍开着) 时,错误后附"设备的响应带长度字节,而程序未启用长度:程序与设备的长度 (G1408)、校验和 (G1407) 设置必须相同…" (反之为"不带长度字节"),以前只报告"无法解析响应 (5 字节)"或"等待响应超时"。
- 数据显示区:向上翻看记录时收到大响应,界面不再卡住 (以前一个 `?` 响应卡 1~2.5 秒,二进制格式约 7 秒)。
- 修改配置窗口打开时,确认框和提示框属于该窗口 (以前属于主窗口:点一下修改配置窗口就把确认框挡在后面,确认框打开时还能修改值或点其他按钮)。
- 健壮性:`Texts.json` 中有重复的键时,启动时显示"无法读取文本文件"并退出 (以前是系统的崩溃框,不写 error.txt);帮助表中格式不正确的 ID (每级不是两位十六进制) 不保存、不写入 (以前写入到该项时报错中断,已写入的项保留,保存的文件也读不回来);修改配置时原值小数超过 28 位不再报错。
- 兼容:0.9.0~0.9.6 的 `settings.json` 和配置文件可以直接使用。

## 发布前检查 (实机)

1. 连接:
   - RS232:选择串口,按设备 G1304/G1305 设置校验和与长度字节,连接成功。
   - TCP:输入设备 IP (端口固定 2101),按设备 G1407/G1408 设置,连接成功;拔掉网线约 15 秒内显示连接中断。
2. 指令:发送 `H01`;发送多条指令 `QG01;QG1304;QG1305`,逐条显示解析结果。
3. 保存配置:约 10 秒完成,生成 `recipe\IMC300_*.json`。
4. 恢复配置:修改设备上的一项设置后恢复,确认框列出差异,恢复后校验一致。
5. 恢复时重新创建:删除设备上的一个材料或膜层后恢复,能重新创建并写入。
6. 修改配置:
   - 来源选"保存的配置":打开配置文件,只读页显示设备当前值;在可写页用下拉框和输入框各修改一项,写入设备并保存文件。
   - 来源选"实机数据":读取设备后修改一项并写入,窗口保持打开,再次修改另一项成功。
7. 再次启动程序:只保留一个窗口,已打开的窗口被切换到前台。
8. 关闭程序后再打开:通讯配置被恢复。
9. 语言:把 `settings.json` 的 `language` 改为 `en` 后重启,界面、对话框和日志为英文,修改配置窗口的名称为设备帮助表的 DESCRIPTION;改回 `auto` 后按系统语言/地区显示。
