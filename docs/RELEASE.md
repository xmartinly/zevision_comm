### 1.2 系统概述

Zevision 是 INFICON IMC300 膜厚控制仪的上位机软件，通过 RS232 或以太网（TCP 端口 2101）以 Zevision 协议与设备通信，用于发送协议指令，以及保存、恢复和修改仪器配置。软件由应用程序 `Zevision.exe` 和 4 个程序集组成：通信库 `Zevision.Communication.dll`、指令集库 `Zevision.Commands.dll`、业务层 `Zevision.Core.dll`、存储层 `Zevision.Storage.dll`。两个链接库另行发布，供生产程序使用。

### 3.3 本版本的更改

1.2.0 相对 1.1.0 的更改见表 6。实机验证见 ZEV-STR-01 的 STR-2026-10-21-01。

表 6  1.2.0 的更改

| 序号 | 项目 | 更改内容 |
|---|---|---|
| 1 | 通信数据文件名 | 文件名改为设备的系统序列号（G06）、连接的日期和时间（到分钟），如 `XXXXXXXX_20261021_1337.txt`；未启用“连接时握手”或设备未返回序列号时，序列号部分为 `unknown`。同一分钟内再次连接（含自动重连）时追加到同一文件。1.1.0 及以前为 `capture_yyyyMMdd_HHmmss.txt`。 |
| 2 | 通信数据文件大小 | 单个文件超过 30 MB 时，后续内容写入在原文件名后加 `_1`、`_2`… 的文件（如 `XXXXXXXX_20261021_1337_1.txt`）；一次通信的显示行不拆到两个文件中。 |
| 3 | 握手 | 读取型号和帧格式设置的查询帧增加 G06：`QG03;QG06;QG1304;QG1305`（以太网为 `QG03;QG06;QG1407;QG1408`）。读不到 G06 时不影响握手。 |
| 4 | 数据显示区刷新 | 程序不在前台（其他程序的窗口在前台，或主窗口最小化）时，数据显示区每 1 s 刷新一次；回到前台时立即显示全部内容。错误日志和通信数据文件不受影响。 |
| 5 | 指令输入框 | 退出时保存最后一次从输入框发送的指令（转为大写后，保留换行），下次启动时显示在输入框中。快捷指令和未发送的修改不保存。 |
| 6 | 鼠标提示 | “保存通讯数据”的提示改为“把显示的数据保存到 logs 目录”。 |
| 7 | 配置文件 | `settings.json` 新增 `lastCommand`；1.1.0 的文件可继续使用，缺少该键时输入框为空。已有的 `capture_*.txt` 保留，不改名。 |
| 8 | 链接库 | 未变（`Zevision.Communication` 1.2.0，`Zevision.Commands` 1.1.0），不另发链接库发布包。 |

### 3.5 安装说明

安装、升级和卸载见 ZEV-OPS-01 第 3 章。要点如下：

1. 将应用发布包解压到可写目录，运行 `Zevision.exe`。软件不需要安装程序。
2. 计算机缺少 .NET Framework 4.7.2 或更高版本时，使用 `_wDotnet` 发布包并运行其中的 `dotnet\ndp48-x86-x64-allos-enu.exe`；已安装时可使用不含安装包的 `_woDotnet` 发布包。
3. 保留原程序目录中的 `settings.json`、`recipes\`（或 1.1.0 之前的 `recipe\`）和 `logs\`。

### 3.6 可能的问题和已知错误

本版本无已知错误。

表 8  可能的问题

| 问题 | 说明 |
|---|---|
| 断开后立即重新连接串口时提示访问被拒绝 | Windows 释放串口需要时间；1 s ～ 2 s 后可以连接 |
| 回显指令 `E` 与其他指令合为一帧时响应无法解析 | 设备的回显延续到帧尾；`E` 应单独成帧发送 |

以下功能尚未在设备上验证（见 ZEV-STR-01 的“待实机确认”）：

- 按编号删除对象（`DM03`、`DF01`、`DL01`、`DP0202`）；
- 新建膜层、工艺（`AL02`、`AP0202`）及工艺膜层的默认值；
- 拔下串口线（非 USB 转换器）后心跳判定中断的时间；
- 写入继电器和输入的引用设置（`N**0B**` 等）。

### 3.7 版本标识规则

1. 应用的版本号只在 `Properties/AssemblyInfo.cs` 中修改：`AssemblyVersion`、`AssemblyFileVersion` 和 `AssemblyInformationalVersion`。
2. 标题栏和 `logs\error.txt` 的会话标题显示 `AssemblyInformationalVersion`。
3. `Zevision.Core` 和 `Zevision.Storage` 的版本与应用相同。
4. 两个链接库的版本独立于应用，位于各自的 `Properties\AssemblyInfo.cs`。公开接口不兼容的修改应提高主版本号。`AssemblyVersion` 保持 1.0.0.0，引用旧版本的程序替换 dll 即可，不需要重新编译。用法和版本变化见 ZEV-CPM-01。
5. ZEV-CPM-02 用于维护本软件，不随链接库发布。

## 4 构建与打包

### 4.1 构建

```
"C:\Program Files (x86)\Microsoft Visual Studio\2019\Community\MSBuild\Current\Bin\MSBuild.exe" Zevision.sln -restore -t:Rebuild -p:Configuration=Release -nologo -v:minimal
```

Release 配置启用 `TreatWarningsAsErrors`，构建结果应为 0 警告。

### 4.2 单元测试

发布前应运行全部单元测试，结果应全部通过：

```
%USERPROFILE%\.nuget\packages\xunit.runner.console\2.9.3\tools\net472\xunit.console.exe Zevision.Tests\bin\Release\Zevision.Tests.dll
```

### 4.3 应用打包

自 1.0.0 起使用打包脚本，输出到 `dist\`（`dist\` 不随源码分发）：

```
powershell -ExecutionPolicy Bypass -File tools\package.ps1
```

脚本按以下顺序执行：

1. 以 Release 配置重新构建并运行全部单元测试（参数 `-SkipBuild` 跳过此步）。
2. 组装发布文件夹。
3. 核对 .NET 安装包的数字签名（签名者 Microsoft Corporation，状态 Valid）。
4. 压缩为两个发布包：含 `dotnet\` 的 `_wDotnet` 和不含 `dotnet\` 的 `_woDotnet`，并核对两者只差 `dotnet\` 中的文件。
5. 输出两个发布包的 SHA256。
6. 将 `_woDotnet` 发布包解压到临时目录并启动一次，核对标题栏中的版本后关闭。程序已在运行时跳过此步并提示手动检查（程序只允许运行一个实例）。

同一版本的输出已存在时，脚本拒绝覆盖。

表 9  应用打包输出

| 输出 | 内容 |

| `dist\Zevision-<版本>\` | 程序目录：`Zevision.exe`、`Zevision.exe.config`、`Texts.json`、`使用说明.md`、`User Guide.md`；`lib\`：表 5 中的 7 个 dll；`dotnet\ndp48-x86-x64-allos-enu.exe`：默认取 `dist` 中最近一个发布包中的文件，或用参数 `-DotNetInstaller` 指定 |

## 附录 A（资料性）历史版本更改

### A.1 1.1.0（相对 1.0.0）

本版本依据《IMC300 / Zevision 上位机软件开发规范》补齐会话层，设计见 ZEV-SDD-01，协议见 ZEV-IDD-01，实机测试见 ZEV-STR-01。

1. 连接时握手：新增协议选项“连接时握手”，默认打开。连接后发送 `H01`，按设备的回答确定帧格式（校验和、长度字节）；与界面设置不同时改用设备的设置并更新开关；读取型号（G03）和帧格式设置。握手成功后状态为“已连接”。握手的收发不显示。关闭该选项时只打开通道，行为与 1.0.0 相同。
2. 传输出错重发：启用握手时，超时、响应帧无效或设备回答 C、L、T 后重发，最多 2 次。只重发动作为 Q、S、U、H、E、`?` 的指令；追加、删除、执行动作的指令不重发。数据显示区显示“第 n/2 次重发 …”。
3. 心跳：启用握手时，连接空闲 5 s 后发送不显示的 `H01`，连续 3 次无应答判定连接中断。软件能够检测串口线断开；TCP 连接不再只依靠约 15 s 的 keep-alive。
4. 自动重连：新增协议选项“自动重连”，默认关闭。连接中断后按 1 s、2 s、4 s … 60 s 的间隔重连并重新握手；点击“断开”停止。
5. 帧格式设置变更：在指令输入框中修改设备的帧格式设置（`UG1304:1` 等）后，按新格式重新握手。
6. 状态错误：设备回答 F（状态不允许）时显示设备当前状态（C09）；恢复和修改配置的错误说明附带该状态。
7. 状态栏：显示正在连接、正在握手和等待重连的状态。
8. 错误指令数：数据显示区标题栏在 TX、RX 之后显示 ERR：没有得到成功响应的指令数（重发后成功的、握手和心跳不计），大于 0 时以错误色显示，“清空”时归零。
9. 通信数据文件：“保存通讯数据”的内容先缓存在内存中，超过 50 KB、断开连接或退出程序时写入 `logs\capture_*.txt`，不再每次通信后写盘。
10. 链接库：`Zevision.Communication` 1.2.0：重发、心跳、优先级排队、连接后改变帧格式；默认参数下行为与 1.1.0 相同。`Zevision.Commands` 未变（1.1.0）。
11. 配置文件：`settings.json` 新增 `handshakeEnabled`（默认 true）和 `autoReconnect`（默认 false）；1.0.0 的文件可继续使用。
12. 仪器配置文件目录：目录改名为 `recipes\`。旧目录 `recipe\` 在第一次保存或打开配置文件时自动改名；`recipes\` 已存在时两者均保留。
13. 鼠标提示：每条提示精简为一句。
14. 发布包：应用发布包分为含 .NET Framework 4.8 离线安装包的 `_wDotnet` 和不含安装包的 `_woDotnet` 两种，由打包脚本一次生成。
15. 文档：新增 ZEV-SRS-01、ZEV-SDD-01、ZEV-IDD-01（命令表由测试与代码比对）、ZEV-STR-01、ZEV-OPS-01；开发规范增加实施状态与偏离说明。

### A.2 1.0.0（相对 0.9.6）

1. 分层重构，功能、界面文字和错误日志内容不变：
   - 硬件通信层与协议解析层：`Zevision.Communication.dll`、`Zevision.Commands.dll`，结构未变；
   - 业务逻辑层：新增 `Zevision.Core.dll`（设备访问、仪器配置读写、恢复计划、修改配置时与设备和文件的同步）；
   - 数据存储层：新增 `Zevision.Storage.dll`（配置文件、`settings.json`、错误日志、通信数据文件），实现业务层定义的接口；
   - 界面层（`Zevision.exe`）只依赖业务层的接口，存储层只在程序启动时组装；
   - 业务层和存储层的提示与错误文本集中在翻译文件 `Texts.json`（中英文），与程序位于同一目录。
2. 发布包结构：程序目录只包含 `Zevision.exe`、`Zevision.exe.config`、`Texts.json` 和使用说明，全部 dll 位于 `lib\` 子文件夹；发布包由 `tools\package.ps1` 生成。升级时删除旧版本程序目录中的 dll（或解压到新文件夹），保留 `settings.json`、`recipe\`、`logs\`。
3. 恢复配置：写入前再次检查设备型号和空闲状态。恢复计划在确认框之前生成，确认期间设备可能已开始工艺；此前版本会写入正在运行的设备。创建对象后才出现的系统设置（如输出源新追加的坩埚材料）写入并校验；此前版本跳过这些设置，报告仍为成功。
4. 修改配置：删除材料前的引用检查包括输出源的坩埚材料。
5. RS232 和 TCP 的校验和、长度字节、保存通讯数据分别保存（设备上为各自的设置 G1304/G1305 与 G1407/G1408），切换连接方式时开关显示该方式上次的设置。0.9.x 的 `settings.json` 中只有一组设置，升级后两种连接方式均沿用该组。
6. 膜系的坩埚号（设备上的选项为 Any、1 ～ 最大数量）：修改窗口中为下拉框（“0 - 任意”、1 ～ 所选输出源的坩埚数量）；写入前检查不超过输出源的坩埚数量（同时修改的输出源按新值检查）；恢复配置时超出的坩埚号不写入，并在确认框中列出原因。
7. `settings.json` 和配置文件可以带 UTF-8 BOM（记事本“另存为 UTF-8”会添加 BOM）。此前版本读取带 BOM 的 `settings.json` 失败，全部设置包括界面语言回到默认值。
8. 链接库 1.1.0（公开接口兼容，详见 ZEV-CPM-01 的版本历史）：连接过程中关闭程序或断开时不留下打开的端口；连接失败时关闭传输；收到的响应不因事件处理慢而被判为超时；大响应只解析一次；指令查找速度约为原来的 3 倍且不分配内存；指令集常驻内存由约 600 KB 降为约 220 KB。
9. 修正 RS232 读取配置失败（实测，固件 1.8.11，2026-10-18）：设备的 RS232 校验和、长度字节均打开（G1304 = G1305 = 1），`?` 的响应却以不带长度和校验和的整帧发送；程序将开头的 `?+` 当作长度，报告“缺少停止符”，其余约 80 KB 显示为“帧外数据”并写入 error.txt。解码器可识别此类响应（`Zevision.Communication` 1.0.1，公开接口不变）。
10. 数据显示区：帮助指令（`?`、`?M` 等）只在指令输入框中发送时显示；保存、恢复、修改配置时读取设备所用的帮助指令及其响应不显示，不保存到通信数据文件，不计入收发帧数；取消读取后设备仍在发送的剩余数据不显示。
11. 修正内存泄漏：此前版本中修改配置窗口关闭后不能被回收，每打开一次托管内存增加约 40 MB（进程私有内存约 50 MB），多次打开后内存占用持续增加。修正后窗口关闭时全部释放。
12. 减少弹窗：操作成功不弹窗，出错时弹窗。
    - 主窗口：保存配置成功、恢复配置成功和“与文件一致，无需修改”只记录在数据显示区；恢复完成但有项无法写入时弹窗。
    - 修改配置窗口：保存、新建、删除、添加或删除列表项的成功结果显示在窗口底部；列表的“+”和工艺的膜层“添加”不再确认（添加的项可以删除）。其他确认框（写入、恢复、新建、删除、删除列表项、放弃未保存的修改、切换语言）不变。
13. 修改配置窗口的“设置”页只为可见的行生成控件（虚拟化）。膜系页“全部展开”的耗时由约 1 s 降为约 0.1 s，内存由约 55 MB 降为约 22 MB；勾选、筛选、滚动的响应更快；外观和操作不变。
14. 帧格式与设备不一致时说明原因：程序与设备的长度字节设置不同（如程序关闭了长度和校验和，设备的 G1407/G1408 仍打开）时，错误信息后附加提示，说明设备的响应带（或不带）长度字节，程序与设备的长度（G1408）、校验和（G1407）设置应相同。此前版本只报告“无法解析响应（5 字节）”或“等待响应超时”。
15. 数据显示区：向上翻看记录时收到大响应，界面不再停顿。此前版本中一个 `?` 响应使界面停顿 1 s ～ 2.5 s，二进制显示格式约 7 s。
16. 修改配置窗口打开时，确认框和提示框的所有者为该窗口。此前版本中所有者为主窗口：点击修改配置窗口会把确认框遮挡在后面，确认框打开时仍可修改值或点击其他按钮。
17. 健壮性：
    - `Texts.json` 中有重复的键时，启动时显示“无法读取文本文件”并退出；此前版本显示系统崩溃框，不写 error.txt；
    - 帮助表中格式不正确的 ID（每级不是两位十六进制）不保存、不写入；此前版本写入该项时报错中断，已写入的项保留，保存的文件无法读回；
    - 修改配置时原值的小数超过 28 位不再报错。
18. 兼容性：0.9.0 ～ 0.9.6 的 `settings.json` 和配置文件可继续使用。
