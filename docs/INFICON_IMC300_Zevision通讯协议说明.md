# INFICON IMC300 / Zevision 通讯协议说明

> 来源：zevision_comm.pdf，IMC300 Operating Manual 074-786-P1A 第7章 Communication。
> 适用设备：IMC300 / Zevision 协议。

---

## 1. 指令结构

### 1.1 物理通信接口

| 接口 | 参数 |
|------|------|
| RS-232 | 115200 bps，8 数据位，无校验，1 停止位，即 8-N-1 |
| Ethernet | 端口 2101，DHCP 或静态 IP（可选） |

主机与设备必须使用相同通信方式，串口参数必须匹配。

### 1.2 基本帧格式

**基本发送帧：**

```
{Command Data}
```

**基本响应帧：**

```
{Command Response Data}
```

- 开始字符：`{`
- 停止字符：`}`

收到开始字符 `{` 之前的字符会被忽略。所有传输以 `{` 开始，以 `}` 结束。

### 1.3 协议选项：长度与校验和

启用长度和校验和后，发送/响应帧格式为：

```
{ 长度高字节 长度低字节 命令数据 校验和 }
```

| 字段 | 说明 |
|------|------|
| Start Character | `{` |
| Data Length | 2 字节，高字节在前，低字节在后 |
| Command Data | 命令数据 |
| Checksum | 1 字节 |
| Stop Character | `}` |

**长度规则：**

- 长度包含所有命令数据，不包含 Start、Stop、Length、Checksum。
- 长度范围：1 到 57000。
- 示例：H01 命令长度为 3，长度字段为 00 03。

**校验和规则：**

- 校验和为 1 字节。
- 对命令数据求和，取无符号模 256。
- 不包含 Start、Stop、Length、Checksum。
- 示例：H02 的校验和为十六进制 AA。

### 1.4 多包传输

当响应超过文档所述上限时，响应会拆分为多个包。文档中同时出现 57,000 和 57,800，建议实际使用不超过 57,000 字节，以设备设置为准。

- 未启用 Length/Checksum 时：每包无头尾，但总响应仍有开始和结束字符。
- 启用 Length 时：每包头部为 `<` + 长度高字节 + 长度低字节。
- 启用 Checksum 时：每包尾部为 校验和 + `>`。
- 总响应始终由开始字符和结束字符标记。

### 1.5 命令语法

**命令结构：**

```
动作 + 命令组 + 命令ID(可多级) + [ :数据 ] + [ ;下一条命令 ]
```

**动作类型：**

| 动作 | 含义 |
|------|------|
| U | Update，更新配置值 |
| Q | Query，查询配置值 |
| A | Add，添加列表项 |
| D | Delete，删除列表项 |
| ? | Help，显示帮助 |
| S | Status，读取运行时变量，并带同步计数 |
| R | Remote，执行动作 |

**命令组：**

| 组 | 含义 |
|----|------|
| C | Process Control，过程控制 |
| E | Echo，回显 |
| F | Film，膜 |
| G | General，通用 |
| H | Hello，握手/版本 |
| I | Inputs，输入 |
| L | Layer，层 |
| M | Materials，材料 |
| N | Sensors，传感器/QCM |
| O | Outputs，输出 |
| P | Process，过程 |
| S | Sources，电源/源 |
| T | Logic，逻辑 |

**命令 ID：**

- 2 个 ASCII 字符，十六进制，范围 00 到 FF。
- 可有多级 ID，例如 G0E03、P02010701。

**数据：**

- 数据分隔符：`:`
- 多命令分隔符：`;`
- 数据可为数字、浮点、字符串、时间。
- 时间格式：HHHH:MM:SS，小时最大 8760，可为 0 时省略；分钟和秒 0-59。
- 字符串不需要引号，部分特殊字符不可用。

**多命令示例：**

```
{SC11;SC12}
```

表示查询当前功率和当前速率。

## 2. 错误信息和处理

### 2.1 响应状态

| 状态 | 含义 |
|------|------|
| + | 成功 |
| - | 失败 |

失败时后面会跟错误码。

### 2.2 错误码

| 错误码 | 含义 | 处理建议 |
|--------|------|----------|
| A | Illegal command，命令不支持 | 检查动作、命令组、命令 ID 是否正确 |
| B | Illegal parameter value，参数值非法 | 检查参数范围和格式 |
| C | Checksum error，校验和错误 | 仅在启用校验和时出现；重新计算命令数据校验和，确认模 256 |
| D | Illegal format，格式非法 | 检查 {}、动作、组、ID、:、; 等分隔符 |
| F | State error，系统状态错误 | 查询当前状态，如 QC09、QC01，切换到允许状态后再发 |
| L | Length error，长度错误 | 仅在启用长度时出现；检查长度字段是否等于命令数据长度 |
| T | Timeout，超时 | 已收到 `{`，但 200 ms 内未收到 `}`；检查停止字符、通信延迟，必要时分包或重发 |

### 2.3 错误处理流程

1. 检查帧是否以 `{` 开始、以 `}` 结束。
2. 若启用长度：先验证长度字段。
3. 若启用校验和：对命令数据求和模 256，验证校验和。
4. 若状态为 `-`，读取错误码。
5. 根据错误码修正命令、参数、状态或通信设置。
6. 建议失败后重试 1-3 次；仍失败则记录原始帧和错误码。

## 3. 反馈解析

### 3.1 响应格式

```
{ 命令回显 + 状态[错误码] [ :数据 ] [ ;下一条响应 ] }
```

**解析步骤：**

1. 找到开始 `{` 和停止 `}`。
2. 如果启用长度/校验和，先校验。
3. 命令回显：数据分隔符 `:` 之前的内容。
4. 状态：`+` 成功，`-` 失败。
5. 如果失败，错误码紧跟在 `-` 后。
6. 数据：通常在 `:` 后，仅查询或状态命令返回。
7. 多命令响应以 `;` 分隔，每条命令都有回显和状态。

### 3.2 状态命令 S 的特殊格式

状态命令 S 会返回同步计数 sync count：

```
+同步计数,数据
```

- 同步计数范围：0-255。
- 每 100 ms 测量递增一次，溢出后回滚。
- 用于判断数据新旧。
- 通常以十六进制 ASCII 表示。

**示例：**

```
{SC11+93,23.82}
```

含义：SC11 当前功率，同步计数 0x93，功率值 23.82。

```
{SC12+22,3.05}
```

含义：SC12 当前速率，同步计数 0x22，速率值 3.05。

### 3.3 常用反馈示例

| 发送 | 响应 | 说明 |
|------|------|------|
| `{QG03}` | `{QG03+IMC300}` | 查询设备名 |
| `{UG0E03:20}` | `{UG0E03+}` | 设置亮度 20% |
| `{SC11}` | `{SC11+93,23.82}` | 查询当前功率，带同步计数 |
| `{SC11;SC12}` | `{SC11+93,23.82;SC12+22,3.05}` | 多命令查询 |

## 5. 快速使用建议

1. 先发 `{H01}` 或 `{H02}` 验证通信。
2. 查询配置用 Q，例如 `{QG03}`。
3. 修改配置用 U，例如 `{UG0E03:20}`。
4. 查询运行状态优先用 S 命令，例如 `{SC11}`、`{SC12}`。
5. 多命令用 `;` 拼接，例如 `{SC11;SC12}`。
6. 若启用长度和校验和，必须严格按 `{长度高 长度低 数据 校验和}` 组帧。
7. 解析响应先看 `+` / `-`；失败读错误码并处理。
8. 状态命令 S 响应中的同步计数用于判断数据新旧，每 100 ms 递增。
