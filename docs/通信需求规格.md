## 1 范围

### 1.1 标识

本文档适用于 Zevision（IMC300 通信测试）软件 1.1.0 版，以及该软件使用的链接库 `Zevision.Communication` 1.2.0 和 `Zevision.Commands` 1.1.0。

### 1.2 系统概述

Zevision 是 INFICON IMC300 膜厚控制仪的上位机测试与配置软件，运行于 Windows，通过 RS232 或以太网（TCP）按 Zevision 协议与仪器通信。软件提供以下功能：

a) 手动发送 Zevision 协议指令，显示收发的原始帧和解析结果；

b) 保存、恢复和修改仪器配置（材料、膜系、膜层、工艺、传感器、输出源、输入输出、逻辑和部分系统设置）。

以下功能不属于本软件：工艺编排与运行控制（不发送 C 组的启动、停止指令）；运行数据的周期性监控和告警。

### 1.3 文档概述

本文档按 GB/T 8567-2006 中“软件需求规格说明（SRS）”编排，规定软件的通信需求及其合格性规定，用语按 GB/T 1.1-2020。剪裁情况：删除“计算机资源需求”“人员需求”“培训需求”“包装需求”“其他需求”条目；外部接口的协议细节由 ZEV-IDD-01 规定，本文档只规定接口需求。需求标识规则见 3.3。

## 3 需求

### 3.1 要求的状态和方式

软件的通信连接处于表 2 所列状态之一。状态转换见 ZEV-SDD-01 的 4.4.2。

表 2  连接状态

| 状态 | 说明 | 允许的操作 |
|---|---|---|
| 未连接 | 通道未打开 | 修改连接设置；连接 |
| 连接中 | 正在打开串口或 TCP 连接 | 无 |
| 握手中 | 通道已打开，正在确认设备和帧格式 | 无 |
| 已连接 | 握手已完成，或未启用握手 | 发送指令；保存、恢复、修改仪器配置；断开 |
| 重连中 | 连接意外中断后，等待下一次自动重连 | 断开（停止自动重连） |

除“未连接”外，连接设置不可修改。

### 3.2 需求概述

#### 3.2.1 目标

软件用于 IMC300 的通信测试和仪器配置的备份、恢复与修改。通信应在帧格式、超时、传输错误和断线等情况下给出确定的结果，不应无限等待，不应在未确认设备的情况下报告“已连接”。

#### 3.2.2 运行环境

运行环境见 3.8。已在 IMC300 固件 1.8.11 上验证（ZEV-STR-01）。

#### 3.2.3 用户特点

用户为设备调试和测试人员，了解 Zevision 协议和 IMC300 的设置项。

#### 3.2.4 约束条件

设计和实现约束见 3.10。

### 3.3 能力需求

需求标识的格式为 `SRS-<类别>-<序号>`。类别：IF 物理接口，FO 协议选项，HS 握手，CMD 指令与仪器配置，REL 可靠性，LOG 日志与诊断，EXT 外部接口，DAT 内部数据，ADP 适应性，SAF 安全性，ENV 环境，QA 软件质量，CON 设计和实现约束。

#### 3.3.1 物理接口

表 3  物理接口需求

| 标识 | 需求 |
|---|---|
| SRS-IF-01 | 软件应能通过 RS232 与 IMC300 通信。串口应从系统枚举，并能重新扫描。 |
| SRS-IF-02 | RS232 的波特率应可选 9600、19200、38400、57600、115200 bit/s，数据格式固定为 8N1。 |
| SRS-IF-03 | 软件应能通过以太网 TCP 与 IMC300 通信。地址为设备 IP 地址（G1402），端口固定为 2101，连接超时为 5 s。 |
| SRS-IF-04 | 同一时刻软件应只连接一台设备。 |
| SRS-IF-05 | RS232 和 TCP 应使用同一套帧编解码与会话逻辑，两者的差异只在通道实现和帧格式设置项。 |

#### 3.3.2 协议选项

表 4  协议选项需求

| 标识 | 需求 |
|---|---|
| SRS-FO-01 | 软件应支持四种帧格式：无长度无校验和、仅长度、仅校验和、长度和校验和。设置项为 RS232 的 G1304（校验和）、G1305（长度），以太网的 G1407、G1408，两个接口相互独立。 |
| SRS-FO-02 | 启用握手时，软件应在连接后按设备的回答确定其帧格式，不依赖界面设置的正确性；界面上的帧格式开关应随之更新并保存。 |
| SRS-FO-03 | 软件发送的帧格式设置修改指令（`UG1304`、`UG1305`、`UG1407`、`UG1408`）被设备接受后，启用握手时软件应按新格式重新握手。 |
| SRS-FO-04 | 握手应能关闭。关闭时软件应按界面开关打开通道，不握手、不重发、不发送心跳，用于观察帧格式不一致时设备的原始回答。 |
| SRS-FO-05 | 帧格式开关和“保存通讯数据”开关应按连接方式分别保存。 |

#### 3.3.3 握手

表 5  握手需求

| 标识 | 需求 |
|---|---|
| SRS-HS-01 | 启用握手时，软件应在 `H01` 按设备的帧格式得到正确回答后继续握手。 |
| SRS-HS-02 | 软件应读取设备型号（G03）。读不到型号时握手失败；型号不是 IMC300 时应给出提示并允许继续。 |
| SRS-HS-03 | 软件应读取当前接口的帧格式设置；与实际使用的帧格式不一致时应给出提示。 |
| SRS-HS-04 | SRS-HS-01～SRS-HS-03 全部满足后，软件才应进入“已连接”状态；握手失败时应断开并显示原因。 |
| SRS-HS-05 | 握手的收发不应显示在数据显示区，也不应计入收发计数；因帧格式无法识别而握手失败时，失败说明应包含收到的字节。 |

#### 3.3.4 指令与仪器配置

表 6  指令与仪器配置需求

| 标识 | 需求 |
|---|---|
| SRS-CMD-01 | 软件生成的指令应全部来自指令集 `ZevisionCommandSet`（ZEV-IDD-01 附录 A），不应手工拼接。 |
| SRS-CMD-02 | 手动输入应允许发送任意指令，包括帮助指令 `?`。命令部分应转为大写，数据部分保持不变；多条指令以 `;` 或换行分隔，合并为一帧发送。 |
| SRS-CMD-03 | 软件内部使用的指令为：`H01`（握手、心跳、分隔符规避），`?` 和 `?X`（读取配置），Q、U（读写设置），A、D（新建、删除对象和列表项），`QG03;QC09`（修改前检查设备）。 |
| SRS-CMD-04 | 软件应能保存、恢复和修改仪器配置，范围为材料、膜系、膜层、工艺、传感器、输出源、输入输出、逻辑和部分系统设置。 |

#### 3.3.5 可靠性

表 7  可靠性需求

| 标识 | 需求 |
|---|---|
| SRS-REL-01 | 同一时刻应只有一个请求在途；排队的请求应按优先级发送，同一优先级按先后发送。 |
| SRS-REL-02 | 响应超时应为空闲超时，可选 500 ms、1000 ms（默认）、2000 ms、5000 ms；帮助指令 `?` 的超时不应小于 2 s。任何请求不应无限等待。 |
| SRS-REL-03 | 启用握手时，超时、响应帧错误、响应无法解析或设备回答 C、L、T 的请求应重发，最多 2 次；只重发动作为 Q、S、U、H、E、`?` 的指令，一帧中含 A、D、R 指令时整帧不重发。 |
| SRS-REL-04 | 读取失败或 TCP 对端关闭时，软件应立即判定连接中断。 |
| SRS-REL-05 | 启用握手时，连接空闲 5 s 后软件应发送心跳，连续 3 次无应答应判定连接中断。以太网连接另启用 TCP keep-alive（空闲 5 s，间隔 1 s）。 |
| SRS-REL-06 | 应能选择自动重连。启用时，连接意外中断后按 1 s、2 s、4 s、8 s、16 s、32 s，之后每 60 s 重新连接并重新握手，直到成功或用户停止；被中断的配置操作和重复发送不应恢复。 |
| SRS-REL-07 | 设备回答 F（状态错误）时，软件不应重发，不应切换设备状态。启用握手时，手动发送的指令得到 F 回答后，软件应查询 C09 并显示设备当前状态；配置操作被 F 拒绝时，错误说明应包含设备当前状态。 |
| SRS-REL-08 | 配置操作的每个阶段应限时 60 s，并能取消；写入后应逐项读回校验；出错时应立即停止，已写入的项不回滚。 |

#### 3.3.6 日志与诊断

表 8  日志与诊断需求

| 标识 | 需求 |
|---|---|
| SRS-LOG-01 | 数据显示区应显示每帧的时间、方向（TX、RX）、内容（ASCII、HEX 或二进制）、解析结果、错误、重发和连接状态变化；标题栏应显示发送帧数、接收帧数和错误指令数（没有得到成功响应的指令，重发后成功的不计，握手和心跳不计）。 |
| SRS-LOG-02 | 应能选择保存通信数据：连接期间显示的内容先保存在内存中，超过 50 KB、断开连接或退出程序时追加到 `logs\capture_*.txt`。 |
| SRS-LOG-03 | 错误、意外异常和每次运行的会话标题应写入 `logs\error.txt`；文件超过 5 MB 时应改名为 `error.1.txt`。 |
| SRS-LOG-04 | 握手、心跳和读取配置所用帮助指令的收发不应显示。 |

### 3.4 外部接口需求

表 9  外部接口需求

| 标识 | 需求 |
|---|---|
| SRS-EXT-01 | 软件与 IMC300 之间的接口应符合 ZEV-IDD-01 规定的物理接口、帧格式、指令、响应和会话规则。 |
| SRS-EXT-02 | 用户界面应提供中文和英文两种语言，界面元素见 ZEV-SUM-01。 |
| SRS-EXT-03 | 文件接口为 `settings.json`、`recipes\*.json`、`logs\error.txt`、`logs\capture_*.txt` 和 `Texts.json`，格式见 ZEV-CPM-02。 |

### 3.5 内部数据需求

表 10  内部数据需求

| 标识 | 需求 |
|---|---|
| SRS-DAT-01 | 连接设置、帧格式开关（按连接方式）、超时、“连接时握手”“自动重连”“保存通讯数据”开关、显示格式、重复发送设置和界面语言应保存在 `settings.json` 中；缺少的项取默认值，文件损坏时使用默认值并报告。 |
| SRS-DAT-02 | 仪器配置文件应为 JSON（`formatVersion` 2），带 MD5 校验；默认目录为程序目录下的 `recipes`。 |
| SRS-DAT-03 | 业务层和存储层的提示文本应来自程序目录下的 `Texts.json`；文件缺失或无效时软件应提示后退出。 |

### 3.6 适应性需求

表 11  适应性需求

| 标识 | 需求 |
|---|---|
| SRS-ADP-01 | 程序目录不可写时，数据文件应保存到 `文档\Zevision\`。 |
| SRS-ADP-02 | 1.0.x 版的 `settings.json` 和配置文件应可继续使用，不需要转换。 |
| SRS-ADP-03 | 1.1.0 之前的 `recipe` 目录应在第一次保存或打开配置文件时改名为 `recipes`；`recipes` 已存在或改名失败时保留旧目录。 |
| SRS-ADP-04 | 界面语言应按 Windows 显示语言或区域格式自动选择，也可在 `settings.json` 中指定；切换语言时软件重新启动。 |

### 3.7 安全性需求

表 12  安全性需求

| 标识 | 需求 |
|---|---|
| SRS-SAF-01 | 软件不应自动切换设备状态（如中止工艺），不应发送 C 组的工艺控制指令。 |
| SRS-SAF-02 | 恢复、修改、新建和删除前，软件应确认设备型号与配置一致且 C09 为 `Ready`。 |
| SRS-SAF-03 | 恢复不应写入通信设置（G13、G14）和工艺控制（C）；修改窗口不应提供 C、G0A、G11、G13、G14 的修改。 |
| SRS-SAF-04 | 写入、恢复、新建、删除对象和删除列表项之前，软件应要求用户确认。 |
| SRS-SAF-05 | MD5 校验失败或格式版本不支持的配置文件应拒绝载入。 |

### 3.8 环境需求

表 13  环境需求

| 标识 | 需求 |
|---|---|
| SRS-ENV-01 | 操作系统为 Windows 7 SP1 及以上版本，运行库为 .NET Framework 4.7.2 或更高版本。 |
| SRS-ENV-02 | 同一台计算机上应只运行一个实例；再次启动时应激活已运行的窗口后退出。 |

注：串口同一时刻只能由一个程序打开；关闭串口后立即重新打开，Windows 可能在短时间内拒绝访问（ZEV-STR-01）。

### 3.9 软件质量因素

表 14  软件质量需求

| 标识 | 需求 |
|---|---|
| SRS-QA-01 | 读取循环、事件处理和界面命令中的意外异常不应终止进程，应写入错误日志。 |
| SRS-QA-02 | 帧编解码器、多包重组器和响应解析器应为不依赖通道、界面和全局状态的组件，能独立进行单元测试；单元测试不应依赖真实设备。 |
| SRS-QA-03 | ZEV-IDD-01 中的帧格式常量、错误码表和命令表应与实现一致，并由自动测试检查。 |
| SRS-QA-04 | 数据显示区最多保留 20000 条记录，超出时成批删除最早的记录；大响应应拆分为多行显示。 |
| SRS-QA-05 | 串口、TCP 连接、计时器和文件应按 ZEV-SDD-01 的 4.4.12 释放；退出过程不应死锁。 |

### 3.10 设计和实现约束

表 15  设计和实现约束

| 标识 | 约束 |
|---|---|
| SRS-CON-01 | 目标框架为 .NET Framework 4.7.2，语言版本为 C# 9，项目文件为非 SDK 格式。 |
| SRS-CON-02 | 界面采用 WPF 和 MaterialDesignThemes 5.3.2。 |
| SRS-CON-03 | 软件按通信库、指令集库、业务层、存储层和界面分层，依赖只指向下层；通信库只引用 .NET Framework。 |
| SRS-CON-04 | 通信库和指令集库不写日志、不读写文件、不依赖界面框架；通信库的结果说明为英文。 |
| SRS-CON-05 | 全部 I/O 应采用异步方法并支持取消令牌；不应使用 `.Result`、`.Wait()` 和 `Thread.Sleep`。 |
| SRS-CON-06 | 协议字节应按 ASCII 编码；设备返回的数值应按 `CultureInfo.InvariantCulture` 解析。 |

## 7 注解

### 7.1 术语

表 20  术语

| 术语 | 定义 |
|---|---|
| 帧 | 以 `{` 开始、以 `}` 结束的一条 Zevision 消息，可含长度字节和校验和 |
| 帧格式 | 帧中是否带长度字节和校验和的组合，由设备的 G1304/G1305（以太网为 G1407/G1408）决定 |
| 握手 | 连接后确认设备应答、确定帧格式并读取型号和帧格式设置的过程 |
| 心跳 | 连接空闲时发送的 `H01`，用于检测断线，不显示 |
| 重发 | 传输出错后再次发送同一帧 |
| 空闲超时 | 从发送或最近一次收到字节起计算的超时 |
| 回显 | 响应中重复的命令部分，用于把响应对应到请求 |
| 多包消息 | 设备把大响应分成多个包发送的消息 |
| 在途请求 | 已发送、尚未收到响应且未超时的请求 |
