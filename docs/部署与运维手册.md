## 1 范围

### 1.1 标识

本文档适用于 Zevision（IMC300 通讯测试）1.3.1 版应用发布包，以及其中的链接库 `Zevision.Communication` 1.2.0 和 `Zevision.Commands` 1.1.0。

### 1.2 系统概述

Zevision 是 INFICON IMC300 膜厚控制仪的上位机软件，运行于 Windows，通过 RS232 或以太网（TCP 端口 2101）以 Zevision 协议与设备通信。软件以压缩包形式发布，解压后运行，不需要安装程序。

### 1.3 文档概述

本文档依据 GB/T 8567-2006 的软件安装计划（SIP）和计算机操作手册（COM）合并编写，规定软件的安装、升级、卸载、运行配置、运行监视和诊断方法。

剪裁情况：软件为单机解压运行，删除 SIP 中的安装进度、安装组织与人员、培训和安装场地条目；COM 中的计算机系统操作条目由第 4 章、第 5 章代替；界面操作见 ZEV-SUM-01，打包和发布材料见 ZEV-SVD-01。

## 3 安装

### 3.1 安装环境

表 2  安装环境

| 项目 | 要求 |
|---|---|
| 操作系统 | Windows 7 SP1 及以上；宜使用 Windows 10 或 Windows 11 |
| 运行库 | .NET Framework 4.7.2 或更高。Windows 10 1803 及以上已内置；其他系统使用 `_wDotnet` 发布包中的 `dotnet\ndp48-x86-x64-allos-enu.exe` 安装 |
| 程序目录 | 应可写，用于 `settings.json`、`configs\`、`recipes\` 和 `logs\`；不可写时软件将这些文件保存到 `文档\Zevision\` |
| 通信接口 | RS232 串口或 USB 转串口线；或与设备同一网段的以太网接口 |
| 设备设置 | RS232：协议类型 G1301 = 0（Zevision）；以太网：协议类型 G1406 = 0（Zevision），IP 地址 G1402 |

### 3.2 安装过程

1. 选择应用发布包：计算机已安装 .NET Framework 4.7.2 或更高版本（Windows 10 1803 及以上已内置）时使用 `Zevision-<版本>_woDotnet.zip`；否则使用含离线安装包的 `Zevision-<版本>_wDotnet.zip`。
2. 将发布包解压到可写目录（如 `D:\Zevision`）。
3. 运行程序目录中的 `Zevision.exe`。
4. 若启动时提示缺少 .NET Framework，以管理员权限运行 `_wDotnet` 发布包中的 `dotnet\ndp48-x86-x64-allos-enu.exe`（离线安装，不需要网络连接，安装后可能需要重启计算机），然后再次运行 `Zevision.exe`。

安装后的程序目录只包含 `Zevision.exe`、`Zevision.exe.config`、`Texts.json`、`materials.json`（材料库）和用户手册，dll 位于 `lib\` 子文件夹。

注 1：软件只允许运行一个实例。再次启动时，已打开的窗口切换到前台，新进程退出。

注 2：`Texts.json` 缺失或损坏时，软件提示后退出（退出码 1）。应从发布包恢复该文件。

### 3.3 升级

从 1.0.x、1.1.0 或 1.2.0 升级到 1.3.1：

1. 关闭 Zevision。
2. 用新版本发布包中的文件替换程序目录中的文件（含新增的 `materials.json`）。
3. 保留程序目录中的 `settings.json`、仪器配置文件目录（1.2.0 和 1.1.0 为 `recipes\`，1.0.x 为 `recipe\`）、`logs\`。

升级后的数据处理如下：

- 1.3.1 新增工艺编辑。材料和工艺保存在 `recipes\` 下的 `material\`、`film\`、`layer\`、`process\` 文件夹中；材料库为程序目录中的 `materials.json`，只读，缺失时材料库为空。
- 新的通信数据文件以设备序列号和时间命名（如 `XXXXXXXX_20261021_1337.txt`，1.2.0 起）；已有的 `capture_*.txt` 保留，不改名。
- 1.1.0 及以前的 `settings.json` 没有 `lastCommand` 键，升级后第一次启动时指令输入框为空。
- 仪器配置文件目录改为 `configs\`（1.3.1 起）：软件第一次使用时把 `recipes\`（1.0.x 为 `recipe\`）改名为 `configs\`；两者都存在时只改名 `recipes\`，`recipe\` 保留；`configs\` 已存在时均保留。之后 `recipes\` 用于工艺编辑的文件。改名失败（如其中的文件被其他程序打开）时，旧文件留在 `recipe\`，在打开文件对话框中仍可找到。
- 1.0.x 的 `settings.json` 没有 `handshakeEnabled` 和 `autoReconnect` 键，升级后“连接时握手”为打开，“自动重连”为关闭。
- 仪器配置文件的格式未变。

从 0.9.x 升级时，应删除旧版本程序目录中的 dll，或将新版本解压到新文件夹。0.9.0 ～ 0.9.6 的 `settings.json` 和配置文件可继续使用。

链接库 `Zevision.Communication` 1.2.0 的 `AssemblyVersion` 仍为 1.0.0.0。引用旧版本的生产程序替换 dll 即可，不需要重新编译；1.2.0 新增的功能默认关闭。

### 3.4 卸载

1. 关闭 Zevision。
2. 删除程序目录。

程序目录可写时，`settings.json`、`configs\`、`recipes\` 和 `logs\` 位于程序目录内，随程序目录一同删除。程序目录不可写时，这些文件位于 `文档\Zevision\`，需要时另行删除。删除前应备份需要保留的仪器配置文件。

## 4 运行配置

### 4.1 连接参数

表 3  连接参数

| 参数 | RS232 | TCP |
|---|---|---|
| 端口或地址 | `COMx`（插拔 USB 转串口线后点击刷新按钮） | 设备 IP 地址（G1402），端口固定为 2101 |
| 波特率 | 与 G1303 一致（出厂 115200 bit/s），数据格式固定为 8N1 | — |
| 协议类型 | G1301 = 0 | G1406 = 0 |
| 帧格式 | G1304 校验和、G1305 长度 | G1407 校验和、G1408 长度 |
| 响应超时 | 500 ms、1000 ms（默认）、2000 ms、5000 ms | 同左 |

“连接时握手”打开时（默认），软件在连接后按设备的回答确定帧格式，不需要预先知道 G1304、G1305（以太网为 G1407、G1408）的值。

### 4.2 配置文件 settings.json

`settings.json` 在程序退出时保存。文件损坏时，软件使用默认值并在数据显示区报告。

表 4  settings.json 中与连接有关的键

| 键 | 默认值 | 说明 |
|---|---|---|
| `connectionType` | `Serial` | 连接方式：`Serial` 或 `Tcp` |
| `portName` | 空 | RS232 端口 |
| `baudRate` | 115200 | RS232 波特率 |
| `tcpHost` | 空 | 设备的 IP 地址 |
| `checksumEnabled`、`lengthEnabled` | false | RS232 的帧格式开关；握手后按设备更新 |
| `tcpChecksumEnabled`、`tcpLengthEnabled` | 与 RS232 相同 | TCP 的帧格式开关 |
| `responseTimeoutMs` | 1000 | 响应空闲超时，单位为 ms |
| `handshakeEnabled` | true | 连接时握手，同时启用重发（2 次）和心跳（间隔 5 s，3 次无应答判定中断） |
| `autoReconnect` | false | 连接意外中断后自动重连 |
| `rawCaptureEnabled`、`tcpSaveCommunicationData` | false | 保存通讯数据（RS232、TCP） |
| `language` | `auto` | 界面语言：`auto`（按系统选择）、`zh` 或 `en` |

### 4.3 数据文件与日志

程序目录可写时，表 5 中的文件位于程序目录；不可写时位于 `文档\Zevision\`。

表 5  数据文件与日志

| 文件 | 内容 | 维护 |
|---|---|---|
| `settings.json` | 界面设置，见表 4 | 退出时保存；损坏时使用默认值并报告 |
| `configs\*.json` | 仪器配置文件，带 MD5 校验 | 手工改动过的文件被拒绝载入 |
| `recipes\material\*.json`、`recipes\film\*.json`、`recipes\layer\*.json`、`recipes\process\*.json` | 工艺编辑中的材料、膜系、膜层和工艺，每个对象一个文件 | 工艺编辑窗口中单击“保存”时写入，并删除不再对应对象的 `.json` 文件；有文件损坏时不打开窗口，错误信息给出文件路径，应从备份恢复或删除该文件 |
| `materials.json`（程序目录） | 材料库：IMC300 操作手册附录 A 的材料表，格式 `{ "materials": [ { "formula": "Al", "material_name": "aluminum", "material_name_zh": "铝", "density": 2.7, "z_ratio": 1.08, "z_ratio_established": true } ] }`；源文件为 `docs\materials.json` | 随程序发布，软件只读取；损坏时记录错误，工艺编辑中不能从材料库选择 |
| `logs\error.txt` | 错误和意外异常（含堆栈）；每次运行的第一条记录前有会话标题 `==== Zevision <版本> \| 系统 \| CLR \| 位数 ====` | 超过 5 MB 时改名为 `error.1.txt` |
| `logs\<序列号>_<日期>_<时间>.txt` | “保存通讯数据”打开时，连接期间数据显示区的内容；文件名如 `XXXXXXXX_20261021_1337.txt`，序列号为设备的 G06，未启用握手时为 `unknown`；先缓存在内存中，超过 50 KB、断开连接或退出程序时写入；单个文件超过 30 MB 时续写到文件名加 `_1`、`_2`… 的文件 | 不自动清理 |

## 5 运行监视

主窗口左下角的状态栏显示链路状态。

表 6  链路状态

| 状态栏显示 | 含义 |
|---|---|
| `未连接` | 通道未打开 |
| `正在连接 COM3, 115200, 8N1 …` | 正在打开串口或 TCP 连接 |
| `正在握手 …` | 正在确认设备和帧格式 |
| `已连接 COM3, 115200, 8N1` | 可以发送指令和进行配置操作 |
| `连接中断,x 秒后第 n 次重连 …` | 自动重连等待中；点击“断开”停止 |

数据显示区按时间顺序显示收发的帧（TX、RX）、解析结果、错误（ERR）、重发和连接状态的变化。标题栏显示发送帧数（TX）、接收帧数（RX）和错误指令数（ERR）；ERR 为没有得到成功响应的指令数，大于 0 时以错误色显示，“清空”时归零。

## 6 诊断

### 6.1 诊断特征概述

软件通过以下途径给出诊断信息：

- 状态栏：链路状态（表 6）；
- 数据显示区：收发的帧、解析结果、错误说明、重发记录、连接状态变化；
- 错误提示框：配置操作出错时弹出；
- `logs\error.txt`：错误和意外异常；
- `logs\<序列号>_<日期>_<时间>.txt`：“保存通讯数据”打开时的通信记录。

### 6.2 诊断步骤

表 7 中的信息按软件显示的原文列出，`…` 和 `<…>` 表示可变部分。

表 7  现象、原因和处置

| 数据显示区的信息 | 可能的原因 | 处置 |
|---|---|---|
| `无法连接 COMx, …: 对端口“COMx”的访问被拒绝。` | 端口被其他程序占用；或刚断开，Windows 尚未释放端口 | 关闭占用端口的程序；等待 1 s ～ 2 s 后再连接 |
| `无法连接 <IP>:2101: 连接超时 (5 秒内无响应)。…` | 网线、IP 地址或网段不正确 | 检查网线和 IP 地址；用 ping 检查设备是否可达 |
| `握手失败: 设备没有应答 H01 (…)。…` | 端口、波特率或 IP 地址不正确；线缆故障；设备未开机 | 逐项检查；RS232 可换用其他串口线或 USB 转串口线测试 |
| `握手失败: 无法识别设备的帧格式 (收到: …)。…` | 多为波特率不正确，收到的是乱码 | 核对 G1303；关闭“连接时握手”后连接，查看原始数据 |
| `设备的帧格式与协议选项不同,已改用设备的设置。` | 设备的 G1304/G1305（G1407/G1408）与界面开关不同 | 无需处置，开关已更新 |
| `设备报告 G1304 = …、G1305 = …,与实际通讯使用的帧格式不一致;…` | 设备报告的设置与实际行为不符 | 记录并反馈；软件按实际使用的格式继续 |
| `设备型号为 <型号>,不是 IMC300;…` | 连接的设备不是 IMC300 | 恢复和修改配置会因型号不符被拒绝 |
| `第 n/2 次重发 <指令>: <原因>` | 线路干扰，或设备暂时没有回答 | 偶尔出现时无需处置；频繁出现时检查线缆、接地和波特率 |
| `连接中断: 设备连续 3 次没有应答心跳。` | 线缆断开、设备断电或设备无响应 | 检查线缆和设备；可打开“自动重连” |
| `连接中断: <系统给出的 I/O 错误说明>` | USB 转串口线被拔出；TCP 对端关闭连接 | 重新插入后连接 |
| `等待响应超时 (… ms 内未收到数据,已收到的不完整数据见上方)。` | 帧格式不一致（未启用握手时）；设备忙 | 打开“连接时握手”；或按提示检查 G1304/G1305 |
| `设备当前状态 (C09): Process` | 设备正在运行工艺，拒绝修改（错误码 F） | 待工艺结束、状态回到 Ready 后再操作 |

### 6.3 错误码处置

表 8  设备错误码的处置

| 代码 | 含义 | 软件的处理 | 操作员的处置 |
|---|---|---|---|
| A | 非法命令 | 显示，不重发 | 检查命令（应为大写）以及对象和字段是否存在 |
| B | 非法参数值 | 显示，不重发；恢复和修改时停止 | 检查值的范围以及引用的对象是否存在 |
| C | 校验和错误 | 可重发的指令自动重发，最多 2 次 | 频繁出现时检查线缆，确认帧格式 |
| D | 非法格式 | 显示，不重发 | 检查命令格式；查询不存在的对象时设备也回答 D |
| F | 状态错误 | 不重发，显示设备当前状态（C09） | 等待设备回到 Ready；软件不自动停止工艺 |
| L | 长度错误 | 同 C | 同 C |
| T | 字符超时（200 ms 内没有收到停止符） | 同 C | 多为帧格式不一致；打开“连接时握手” |

各错误码的协议定义见 ZEV-IDD-01。

### 6.4 诊断工具

#### 6.4.1 通信数据文件

收集通信问题的诊断信息：

1. 断开连接，打开“保存通讯数据”。
2. 将显示格式设为 HEX。
3. 连接设备并重现问题。
4. 断开连接后（通信数据在断开时写入），提供对应的通信数据文件（`logs\<序列号>_<日期>_<时间>.txt`）和 `logs\error.txt`。

#### 6.4.2 错误日志

`logs\error.txt` 记录错误、意外异常及其堆栈。反馈问题时应附带该文件。文件格式见表 5。

#### 6.4.3 原始帧探测工具

`tools\probe.ps1` 按指定的帧格式（P 无长度无校验和、L 长度、C 校验和、LC 两者）发送原始帧，并显示设备回答的文本和十六进制。使用前应关闭 Zevision（串口同一时刻只能由一个程序打开）。用法和测试记录见 ZEV-STR-01。

```powershell
powershell -ExecutionPolicy Bypass -File tools\probe.ps1 -Port COM3 -Steps 'P|H01','LC|H01','P|QG1304;QG1305'
powershell -ExecutionPolicy Bypass -File tools\probe.ps1 -TcpHost 192.168.5.88 -Steps 'LC|H01','LC|SC11;SC12'
```

修改设备设置的探测（如 `UG1305:1`）结束后，应改回原值并用查询确认。

## 7 注解

表 9  术语和缩略语

| 术语或缩略语 | 说明 |
|---|---|
| SIP | 软件安装计划（Software Installation Plan） |
| COM | 计算机操作手册（Computer Operation Manual） |
| 握手 | 连接后确认设备应答、确定帧格式并读取型号的过程，见 ZEV-IDD-01 |
| 心跳 | 连接空闲时周期发送的 `H01`，用于检测断线 |
| 帧格式 | 帧中是否带长度字节和校验和，由设备的 G1304/G1305（以太网为 G1407/G1408）决定 |
| 通信数据文件 | “保存通讯数据”打开时生成的 `logs\<序列号>_<日期>_<时间>.txt` |
| C09 | 设备的当前状态项，空闲时为 `Ready` |
| keep-alive | TCP 保活探测，空闲 5 s 后每 1 s 探测一次 |
