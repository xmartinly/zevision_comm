# IMC300 / Zevision 上位机软件开发规范（.NET Framework 4.7.2）

> 适用设备：INFICON IMC300 / Zevision
> 物理接口：RS-232（115200-8-N-1）或 Ethernet（TCP 端口 2101）
> 协议依据：IMC300 Operating Manual 074-786-P1A 第7章 / Zevision 通讯协议说明
> 文档性质：工程开发规范，只约束做法，不复述指令细节
> 版本：v1.0

---

## 1. 分层与边界

| 层 | 只做 | 绝不做 |
|---|---|---|
| 物理通信层 | 串口/TCP 字节收发、连接状态维护 | 解析帧、识别定界符、处理协议选项 |
| 协议编解码层 | 帧定界、长度与校验和、多包重组、命令/响应编解码 | 依赖 UI、持有通信通道 |
| 会话层 | 命令队列、请求响应匹配、超时重试、握手、状态轮询、错误码处置 | 操作字节流、写 UI |
| 业务层 | 工艺编排、数据落盘、告警 | 阻塞等待、调用 UI 线程 |
| 表示层 | 数据绑定、用户输入、状态展示 | 写协议逻辑、直接调用通信层 |

约束：

- 串口与 TCP 必须复用同一套编解码与会话逻辑，差异只保留在通道实现与协议选项配置。
- 通道由工厂按配置创建，业务层与表示层不得出现 `SerialPort` / `TcpClient` 的直接实例化。
- 协议层不得引用任何 UI 程序集；表示层不得引用物理通信层。

## 2. 协议层硬性约束

### 2.1 协议选项

- 长度检查与校验和开关必须在连接后从设备读取实际值，写入编解码配置，全程一致。
- 禁止在代码中硬编码选项状态；配置变更后必须重新查询。
- 串口与以太网各自维护选项，互不推断。

### 2.2 长度字段

- 2 字节，高字节在前、低字节在后。
- 只计命令数据，不含起始符、停止符、长度字段本身、校验和。
- 范围 1–57000；超过上限按多包处理，单包设计上限取 57000，不采用 57800。

### 2.3 校验和

- 1 字节，对命令数据求和后模 256。
- 不含起始符、停止符、长度字段、校验和本身。

### 2.4 帧定界与重组

- 接收侧以停止符与长度字段双策略定界；起始符之前的字节一律丢弃。
- 多包重组必须覆盖三种形态：未启用长度、启用长度（分包头）、启用校验和（分包尾）。
- 重组器输出完整逻辑响应后才上交会话层，不得把分包直接交给业务层。
- 超出单包上限的响应继续拼接，直到遇到总停止符。

### 2.5 多命令与响应匹配

- 多条命令用分号拼接发送，响应用分号分隔。
- 响应必须按其中的命令回显逐条匹配到请求，禁止按到达顺序盲配。
- 回显不匹配视为协议异常，记录原始帧、回显与期望命令。

### 2.6 状态命令的同步计数

- 状态类命令响应中的同步计数每 100 ms 递增，溢出回滚，范围 0–255。
- 会话层必须用同步计数判断数据新旧：计数未变化视为设备未刷新，丢弃该值，不触发业务更新。
- 禁止用时间戳代替同步计数做新旧判断。

### 2.7 组件质量

- 编解码器、重组器、响应解析器必须是可独立单元测试的纯组件，不依赖网络、UI、全局状态。

## 3. 会话层约束

### 3.1 握手

- 连接成功后依次完成：身份与版本校验、读取协议选项、设备名校验。
- 全部通过才置为“已连接”；未完成不得通知上层可用。
- 握手失败置为故障态，进入重连流程。

### 3.2 请求-响应模型

- 同一时刻只允许一个请求在途。
- 业务命令与状态轮询共用命令队列串行执行。
- 高优先级命令（停止、复位）可插队，状态轮询为低优先级。

### 3.3 超时

- 以设备规定的帧内超时为基准，取 3–10 倍作为命令超时，可配置。
- 超时后按错误码分级策略处理，禁止无限等待。

### 3.4 错误码分级处置

| 类别 | 处置 |
|---|---|
| 命令不支持、参数非法、格式非法 | 不重试，记录命令、回显、错误码并上报 |
| 校验和错、长度错、超时 | 重试 1–3 次；仍失败则记录原始帧与错误码 |
| 系统状态错 | 先查询当前状态，切换到允许状态后再重试 |

- 重试仍失败必须上报业务层，禁止静默吞掉。
- 每次重试记录次数、错误码、原始帧。

### 3.5 参数校验前置

- 所有可写参数按协议规定范围在本地校验，越界直接拒绝，不发往设备。
- 字符串参数不得包含协议保留字符。
- 时间参数按协议规定格式与上限校验。

### 3.6 连接与重连

- 重连采用指数退避：1s → 2s → 4s → … → 60s 上限。
- 重连成功后重走握手，再恢复状态轮询。
- TCP 长连接必须有应用层心跳，连续 3 次无应答判定断线；仅靠 Socket KeepAlive 不算。
- TCP 读取返回 0 表示对端关闭，立即触发断线处理。

### 3.7 状态轮询

- 轮询周期建议 100–500 ms，可配置。
- 轮询命令集外置配置，按业务需求裁剪。
- 轮询与业务命令共用队列，轮询期间收到高优先级命令立即让路。
- 轮询结果经同步计数判新旧后再推送。

## 4. 线程模型

| 线程 | 职责 | 约束 |
|---|---|---|
| UI 线程 | 显示、输入 | 不阻塞、不直接调用通信 |
| 通信读线程 | 读字节 → 重组 → 解析 | 不做业务判断 |
| 命令队列消费线程 | 唯一写通道的地方，串行发命令、等响应、重试 | 不得并发写 |
| 状态轮询线程 | 按周期投递命令 | 只投递不执行 |
| 日志线程 | 异步写收发十六进制、错误码、状态迁移 | 不阻塞主链路 |

- 跨线程更新 UI 一律经 `BeginInvoke` / `Dispatcher.BeginInvoke`。
- 通信层异步调用一律 `ConfigureAwait(false)`。
- 禁止 `async void`（事件处理器除外）。
- 禁止用 `Thread.Sleep` 做超时等待，统一用 `Task.Delay` + 取消令牌。

## 5. 配置、日志与资源

### 5.1 配置

以下内容必须外置配置，禁止硬编码：

- 串口参数、IP/端口
- 协议选项（长度、校验和）
- 命令超时、重试次数、重连上限
- 轮询周期与轮询命令集
- 日志级别与路径

### 5.2 日志

必备字段：

- 时间戳
- 方向（发送/接收）
- 原始十六进制
- 命令回显
- 成功/失败
- 错误码
- 同步计数
- 连接状态迁移

约束：

- 日志写入走独立线程，接收回调中禁止同步写文件。
- 通信模块初始化前先确保日志可用。

### 5.3 资源释放

- 串口必须 `Dispose`，仅 `Close` 不够。
- TCP 客户端、网络流、取消令牌源全部纳入释放链。
- 关闭顺序：取消 → 结束队列 → 停轮询 → 断通道 → 释放编解码与通道。
- 退出过程不得死锁，队列先取消再完成。

## 6. 开发流程与文档

| 阶段 | 产物 | 重点 |
|---|---|---|
| 需求 | 通信需求规格 | 物理接口、协议选项开关、握手命令、轮询集合、工艺命令清单 |
| 概要设计 | 概要设计说明书 | 分层、线程模型、通道/编解码/会话三层接口、多包重组方案 |
| 详细设计 | 协议规格书 + 详细设计 | 帧格式表、命令表（动作/组/ID/数据/范围）、错误码表、同步计数说明、多包规则、时序图（连接/握手/单命令/多命令/重连/轮询） |
| 实现 | 代码 + 单元测试 | 编解码、重组、响应解析、错误码映射、同步计数必须有单测 |
| 联调 | 联调记录 | 实际串口/IP、协议选项实际状态、十六进制日志片段、错误码复现步骤 |
| 交付 | 部署与运维手册 | 连接参数、日志路径、链路状态排查、错误码处置表 |

### 单元测试最低覆盖

- 正常帧
- 粘包
- 半包
- 多包
- 校验和错
- 长度错
- 超上限大帧
- 各类错误码（A/B/C/D/F/L/T）
- 同步计数新旧判断

### 评审要求

- 概要设计与详细设计必须评审通过后方可进入实现。

- 联调记录必须包含实际抓包或日志片段。

## 8. 不可裁剪的底线

以下七项直接决定能否稳定对接 IMC300，省略任一项都会在联调阶段付出返工代价：

1. 通道抽象（串口与 TCP 共用接口）
2. 协议选项从设备读取，不硬编码
3. 多包重组器（覆盖三种形态）
4. 状态命令同步计数判新旧
5. 错误码分级重试
6. 握手时序（未完成不置已连接）
7. 资源释放链

### 9.3 偏离说明

表 9-3  偏离说明

| 序号 | 条款 | 偏离内容 | 理由 |
|---|---|---|---|
| 1 | §2.1 | 连接后不先读取 G1304、G1305，而是先用界面设置发送 `H01`；回答不正确时从设备的错误回答识别帧格式，改用后确认，再读取设置核对 | 帧格式未知时无法读取设置项；设备对任何输入都按自身的帧格式回答（ZEV-STR-01） |
| 2 | §3.4 | 只重发动作为 Q、S、U、H、E、`?` 的指令，一帧中含 A、D、R 指令时整帧不重发；重发次数为 2 | 超时不能证明设备未执行；A、D、R 重复执行后设备状态不同 |
| 3 | §3.4 | 设备回答 F 时不切换设备状态、不重试，查询 C09 后与错误一同报告 | 自动切换设备状态（如中止工艺）对镀膜设备存在安全风险 |
| 4 | §4 | 命令队列消费线程、状态轮询线程和日志线程以异步任务实现（发送锁、读取循环、心跳任务、后台写入链）；`ICommand.Execute` 中的 `async void` 视同事件处理程序；跨线程更新界面使用 `SynchronizationContext.Post` | 效果与专用线程相同，占用资源少；在 WPF 中 `SynchronizationContext.Post` 等同于 `Dispatcher.BeginInvoke` |
| 5 | §3.2 | 高优先级请求只排在等待中的请求之前，不打断正在接收的响应（如约 10 s 的完整帮助） | 协议同一时刻只允许一个请求在途 |
| 6 | §3.1 | 型号不是 IMC300 时提示，不拒绝连接 | 通信测试也用于其他型号；恢复和修改在写入前另行核对型号 |
| 7 | §5.3 | 会话的取消令牌源不释放；其他令牌源（等待计时、自动重连）均释放 | 该令牌源没有计时器和关联令牌，不持有非托管资源；连接中断和主动断开可能在不同线程上结束会话，释放后再取消会引发异常 |
| 8 | §3.6 | 自动重连默认关闭，可在协议选项中打开 | 测试场合断线后通常先检查现场 |
| 9 | §3.1、§3.4、§3.6 | “连接时握手”可以关闭；关闭后只打开通道，不握手、不重发、不发送心跳，行为与 1.0 版相同；默认打开 | 用于观察帧格式不一致时设备的原始回答 |
| 10 | §2.2 | 多包消息最后一个续包的长度字段多计包尾（校验和与 `>`）时，在校验和正确的条件下按实际数据读出 | 固件 1.8.11 的缺陷（ZEV-STR-01） |
